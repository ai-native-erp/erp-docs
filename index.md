## Architecture principles (from the retail reference)

> Master data must be changeable without friction. Every transaction that touches value must post to Finance.

1. **Modular monolith** with bounded contexts (procurement, inventory, POS, finance). Split out services later only when load demands.
2. **Event-sourced stock ledger.** On-hand quantity is a projection over an immutable movement stream — never a mutable column.
3. **Outbox + ack sync (HO ↔ store).** Every transaction is written to a durable local queue first, replayed with idempotency keys, and stamped "synced" only on an explicit acknowledgment. Both directions are built symmetrically.
4. **Rules/approval engine as a shared service.** Margin thresholds, MBQ limits, discount caps, reprint gating — one pattern, used everywhere.

## How this site is built

This site is regenerated by `tools/build_pages_site.py`. Run it after every
`tools/generate_odoo_ai_team.py` / `tools/extract_odoo_domain_knowledge.py` /
`tools/generate_base_platform_knowledge.py` cycle to keep pages in sync with
the regenerated knowledge base.
